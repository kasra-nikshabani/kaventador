# معماری پروژه کاوِنتادور

سند مرجع تصمیم‌های فنی. قبل از افزودن هر قابلیت جدید، این سند را بخوانید.

## استک

| لایه | انتخاب |
| --- | --- |
| فریم‌ورک | Next.js 16 (App Router) + React 19 |
| زبان | TypeScript (strict) |
| استایل | Tailwind CSS v4 (پیکربندی CSS-first در `globals.css`) |
| فونت | Vazirmatn variable، محلی از `src/assets/fonts` |
| آیکون | lucide-react |
| تم | next-themes با استراتژی کلاس |

## لایه‌بندی داده

```
                                          ┌→ prisma-*.ts  → PostgreSQL
کامپوننت‌ها → lib/services → lib/repositories ┤
                                          └→ mock-*.ts    → data/*.mock.ts
```

`DATA_SOURCE` انتخاب می‌کند کدام شاخه فعال باشد: `prisma` یا `mock`.
انتخاب یک بار هنگام بارگذاری ماژول انجام می‌شود و لایه‌های بالاتر از آن
بی‌خبرند — به همین دلیل اتصال دیتابیس حتی یک خط از سرویس‌ها و
کامپوننت‌ها را تغییر نداد.

قواعد الزامی:

1. کامپوننت‌ها **هرگز** مستقیم از `data/` یا از کلاینت Prisma import
   نمی‌کنند؛ فقط از `lib/services`.
2. همه توابع لایه سرویس **`async`** هستند. همین یک قاعده بود که اجازه
   داد افزودن Prisma یک تغییر موضعی بماند.
3. تایپ‌های دامنه در `src/types` تعریف می‌شوند و منبع حقیقت‌اند.
   شکل جدول‌ها تابع آن‌هاست، نه برعکس.
4. شکل لایه داده در `lib/repositories/contracts.ts` قرارداد شده و **هر
   دو** پیاده‌سازی با `satisfies` به آن گره خورده‌اند؛ انحراف امضا خطای
   کامپایل می‌دهد نه خطای زمان اجرا. این تنها چیزی است که مانع واگرایی
   بی‌سروصدای دو پیاده‌سازی می‌شود.
5. ترجمه بین ردیف و دامنه فقط در `prisma-mappers.ts` انجام می‌شود.
   شکل رابطه‌ای نباید به بالا نشت کند: جدول `Course` سه ستون تخت برای
   قیمت دارد، دامنه یک شیء `CoursePricing`.

### دیتابیس

- PostgreSQL؛ `docker-compose.yml` نسخه توسعه را روی پورت ۵۴۳۴ بالا
  می‌آورد (نه ۵۴۳۲، تا با نمونه‌های دیگر همان ماشین تداخل نکند).
- مهاجرت‌ها در `prisma/migrations/` نسخه‌بندی شده‌اند.
- `prisma/seed.ts` همان داده `data/*.mock.ts` را می‌نویسد و شناسه‌ها را
  عیناً حفظ می‌کند، پس ارجاع‌های ثابتِ داخل کد نمی‌شکنند.
- **پیشرفت دانشجو ستون ندارد.** فقط `completedLessonIds` ذخیره می‌شود و
  درصد همیشه محاسبه می‌شود؛ وگرنه با تغییر سرفصل، عدد ذخیره‌شده کهنه
  می‌ماند.

## پیکربندی محیط

- `src/config/env.ts` — متغیرهای عمومی (در باندل مرورگر دیده می‌شوند).
- `src/lib/config/server-env.ts` — متغیرهای سروری، با `import "server-only"`
  که مانع نشت تصادفی به کلاینت می‌شود.

هر دو با zod اعتبارسنجی می‌شوند و مقدار نامعتبر **همان ابتدا** شکست
می‌دهد، نه وسط کار کاربر. نمونه کامل: [`.env.example`](../.env.example)

## قواعد RTL

- `<html lang="fa" dir="rtl">` در `src/app/layout.tsx`.
- کلاس‌های جهت‌دار فیزیکی **ممنوع**: `ml-` `mr-` `pl-` `pr-` `left-` `right-`
  `text-left` `text-right` `border-l` `border-r`.
- معادل منطقی **الزامی**: `ms-` `me-` `ps-` `pe-` `start-` `end-`
  `text-start` `text-end` `border-s` `border-e`.
- اعداد و تاریخ‌ها همیشه از `lib/utils/format.ts` عبور می‌کنند.
- بلوک‌های کد و مقادیر انگلیسی با `dir="ltr"` علامت‌گذاری می‌شوند.

## سیستم طراحی

توکن‌ها در `src/app/globals.css` تعریف شده‌اند و دو نسخه دارند (`:root` و `.dark`).

**قاعده:** هیچ کامپوننتی رنگ خام Tailwind (مثل `bg-gray-900`) نمی‌گیرد.
فقط توکن‌های معنایی: `background` `surface` `surface-2` `surface-3`
`foreground` `muted` `subtle` `border` `border-strong`
`primary` `accent` `success` `warning` `danger`.

ابزارهای اختصاصی: `text-gradient`، `bg-grid`، `skip-link`،
`terminal-cursor`، `terminal-prompt`، `code-chip`، `scanlines`،
`drawer-panel`.

**تم تیره پیش‌فرض است** و تمِ طراحی‌شده سایت؛ تم روشن نسخه جایگزین آن
است. هر دو روی یک هیو پایه (فیروزه‌ای) ساخته شده‌اند.

لهجه ترمینالی عمداً محدود و هدفمند است — نوار ترمینال در هیرو، نشانگر
چشمک‌زن در لوگو، چیپ کد برای اسلاگ و نام فناوری. هدف حس فنی است، نه
کلیشه «متن سبز روی مشکی».

**دو فونت:** وزیرمتن برای همه متن، JetBrains Mono فقط برای بافت‌های فنی.
یک فونت TTF سوم هم هست که **فقط سرور** می‌خواندش و به مرورگر نمی‌رود —
برای رندر تصاویر Open Graph، چون `next/og` فرمت woff2 نمی‌پذیرد.

## احراز هویت

یک سیستم برای کل سایت — پنل مدیریت ورود جداگانه ندارد و با **بررسی
نقش** محافظت می‌شود.

| لایه | فایل | نقش |
| --- | --- | --- |
| رمز عبور | `lib/auth/password.ts` | هش `scrypt`، مقایسه با زمان ثابت |
| نشست | `lib/auth/session.ts` | کوکی امضاشده با HMAC-SHA256 |
| محدودیت نرخ | `lib/auth/rate-limit.ts` | ۸ تلاش، قفل ۱۵ دقیقه |
| نگهبان دسترسی | `lib/auth/authorize.ts` | `requireAdmin`، `requireInstructor`، `requireCourseAccess` |
| ناوبری | `proxy.ts` | بررسی خوش‌بینانه وجود کوکی |

**سه لایه دفاع، به این ترتیب:**

1. `proxy.ts` فقط *وجود* کوکی را می‌بیند — نه امضا را راستی‌آزمایی می‌کند
   نه نقش را می‌داند. صرفاً کاربر ناشناس را زود برمی‌گرداند.
2. لِی‌اوت پنل امضا و نقش را بررسی می‌کند.
3. **هر Server Action خودش دوباره بررسی می‌کند** — چون proxy اصلاً
   اکشن‌ها را نمی‌بیند و بدون این، هر کسی می‌توانست مستقیم درخواست بفرستد.

قاعده: هیچ‌وقت proxy را تنها خط دفاع نگذارید.

### سه نقش

| نقش | پنل | دامنه دید |
| --- | --- | --- |
| `student` | `/dashboard` | فقط دوره‌های ثبت‌نام‌شده خودش |
| `instructor` | `/instructor` | فقط دوره‌هایی که `instructorId`شان برابر `personId` اوست |
| `admin` | `/admin` (و `/instructor`) | همه‌چیز |

دو نکته که راحت اشتباه می‌شوند:

- **`User` و `Person` یکی نیستند.** دوره به `Person` ارجاع می‌دهد (چهره
  عمومی) و ورود با `User` انجام می‌شود. پل بینشان `user.personId` است.
  حساب مدرس بدون `personId` به پنل مدرس راه ندارد، چون «دوره‌های من»
  بی‌معنا می‌شود.
- **مالکیت را از فرم نگیرید.** `saveInstructorCourseAction` مقدار
  `instructorId` فرم را دور می‌ریزد و از نشست می‌گذارد؛ اکشن‌های سرفصل
  هم `courseId` فرم را با `requireCourseAccess` می‌سنجند. مخفی‌بودن دکمه
  در رابط کاربری، کنترل دسترسی نیست.

## رسانه

فایل‌های آپلودی عمداً بیرون از `public/` می‌نشینند و از `/api/media/...`
سرو می‌شوند:

- `public/` دارایی build است، نه داده زمان اجرا.
- فایل داخل `public/` همیشه عمومی است؛ با مسیر اختصاصی می‌توان بعداً
  کنترل دسترسی گذاشت.
- مسیر اختصاصی از **هدر Range** پشتیبانی می‌کند — بدون آن، جابه‌جایی روی
  نوار زمان ویدیو کار نمی‌کند و مرورگر باید کل فایل را دانلود کند.

نام فایل کاربر هرگز استفاده نمی‌شود؛ نام تصادفی با پسوندی از نوع MIME
تأییدشده ساخته می‌شود و هر مسیری که از پوشه آپلود بیرون بزند رد می‌شود.

## ساختار پوشه‌ها

```
src/
├─ app/
│  ├─ (site)/     صفحات عمومی — لِی‌اوت با هدر و فوتر
│  ├─ (admin)/    پنل ادمین در مسیر /admin — لِی‌اوت سایدبار
│  └─ layout.tsx  ریشه: lang/dir/font/theme/metadata
├─ components/
│  ├─ ui/         پرایمیتیوهای بی‌طرف و بدون منطق دامنه
│  ├─ layout/     هدر، فوتر، ناوبری، سوییچ تم
│  ├─ shared/     اجزای مشترک بین بخش‌ها
│  ├─ home|course|blog|admin/   کامپوننت‌های مخصوص هر حوزه
│  └─ providers/  کانتکست‌های کلاینتی
├─ lib/
│  ├─ services/     API مصرفی UI
│  ├─ repositories/ نقطه تعویض mock ↔ دیتابیس
│  ├─ db/           کلاینت Prisma (تک‌نمونه)
│  ├─ utils/        cn، فرمت فارسی، slugify
│  ├─ seo/          JSON-LD و قالب تصویر Open Graph
│  ├─ auth/         رمز، نشست، محدودیت نرخ
│  ├─ actions/      Server Actionها و اسکیمای zod آن‌ها
│  ├─ media/        ذخیره‌سازی فایل آپلودی
│  └─ config/       متغیرهای محیطی سروری
├─ data/     داده تایپ‌شده — هم منبع حالت mock، هم ورودی seed
├─ types/    تایپ‌های دامنه
├─ config/   پیکربندی برند و منوها
├─ generated/ کلاینت تولیدشده Prisma (دست‌نویس نیست)
└─ assets/   فونت‌ها
```

```
prisma/
├─ schema.prisma    شکل جدول‌ها
├─ migrations/      تاریخچه نسخه‌بندی‌شده
└─ seed.ts          پرکردن اولیه از data/
```

## قواعد کدنویسی

1. **Server Component پیش‌فرض**؛ `"use client"` فقط برای تعامل واقعی.
2. HTML معنایی و سلسله‌مراتب درست عنوان‌ها (`h1` یکتا در هر صفحه).
3. هر صفحه `generateMetadata` مخصوص خودش دارد.
4. دسترس‌پذیری: skip-link، `focus-visible` واضح، `aria-label` فارسی، کنتراست AA.
5. نام فایل‌ها kebab-case؛ نام کامپوننت‌ها PascalCase.
